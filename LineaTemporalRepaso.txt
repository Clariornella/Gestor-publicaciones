FASE 1: DOMINIO BASE EN NODE.JS (SEMANA 1 · DIA 1)
--------------------------------------------------------------------------------
Contexto:
Todo se ejecutaba por consola con Node.js en una única carpeta raíz (sin servidor,
sin pruebas automatizadas, sin frontend).

Estructura:
gestor-publicaciones/
├── package.json
├── Publicacion.js
└── main.js

Archivos y cambios:
* Publicacion.js (NACE):
  - Como estaba:
    constructor(titulo, descripcion, autor) {
      this.titulo = titulo;
      this.descripcion = descripcion;
      this.autor = autor; // autor era un string plano
      this.fechaPublicacion = new Date();
      this.activa = true;
    }
    Metodos: mostrarResumen() (combinaba titulo y autor) y estaActiva().
  - Por que cambio:
    Un string plano no permitia asociar datos reales del usuario (como email).

* main.js (NACE):
  - Como estaba:
    Script simple para ejecutar con "node main.js". Creaba un array suelto de
    publicaciones, filtraba activas y probaba JSON.stringify(publicaciones).
  - Por que cambio:
    Un array suelto no encapsula la administracion de la coleccion.

FASE 3: HERENCIA, POLIMORFISMO Y ROLES (SEMANAS 1 Y 2 · DIAS 3 A 5)
--------------------------------------------------------------------------------
Contexto:
El dominio se especializa en subclases con extends y super(), evitando condicionales.

Estructura:
gestor-publicaciones/
├── Publicacion.js
├── PublicacionVenta.js
├── PublicacionServicio.js
├── Usuario.js
├── RepositorioPublicaciones.js
└── main.js

Archivos y cambios:
* PublicacionVenta.js (NACE):
  - Como estaba:
    extends Publicacion. constructor(titulo, descripcion, autor, precio) llamando
    a super(titulo, descripcion, autor). Atributos propios: this.precio y this.stock = 1.
    Sobreescribe mostrarResumen() reutilizando super.mostrarResumen() + precio.

* PublicacionServicio.js (NACE):
  - Como estaba:
    extends Publicacion. constructor(titulo, descripcion, autor, modalidad, duracionMinutos).
    Sobreescribe mostrarResumen() con super.mostrarResumen() + modalidad y minutos.

* Usuario.js (MODIFICADO):
  - Como cambio:
    Se agrega auto-asociacion: this.contactos = [] y agregarContacto(otroUsuario).

* Publicacion.js y PublicacionServicio.js (MODIFICADOS - ROLES):
  - Como cambio:
    En Publicacion se consolida this.autor; en PublicacionServicio se agrega this.cliente.
    Ambos referencian a instancias de Usuario cumpliendo roles distintos.

* RepositorioPublicaciones.js (MODIFICADO):
  - Como cambio:
    Suma metodos polimorficos: listarResumenes() (con .map) y filtrarPorTipo(claseConstructor).
    (En el Dia 6 hereda temporalmente de EventEmitter con this.emit("publicacionAgregada"),
    lo cual se retira al migrar a la web).

Estructura:

├── routes/
│   └── publicaciones.routes.js
├── server.js
├── src/...
└── tests/
    └── repositorio.test.js

Archivos y cambios:
* src/Publicacion.js (MODIFICADO):
  - Recibe id como primer argumento opcional: constructor(id, autor, titulo, ...).
  - Publicacion no genera ni valida el id; solo lo almacena (this.id = id).
  - PublicacionVenta y PublicacionServicio se adaptan para reenviarlo con super().

* src/RepositorioPublicaciones.js (MODIFICADO - CRUD EN MEMORIA):
  - Incorpora this.proximoId = 1.
  - agregar(): Asigna this.proximoId++ a la nueva instancia.
  - listar(): Devuelve copia superficial [...this.publicaciones] para encapsulamiento.
  - buscarPorId(id): Busca con Number(id) para tolerar strings.
  - actualizar(id, cambios): Reconstruye con new Publicacion(...) para revalidar reglas.
  - eliminar(id): Remueve con splice y retorna booleano.

* routes/publicaciones.routes.js (NACE):
  - Fabrica crearRouterPublicaciones(repositorio) montando GET / y POST / bajo Express Router.

* server.js (MODIFICADO):
  - Monta el router modular con app.use("/publicaciones", crearRouterPublicaciones(repositorio)).

* tests/repositorio.test.js (REESCRITO):
  - Pruebas unitarias de CRUD en memoria usando beforeEach aislando cada caso.
